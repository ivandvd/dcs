# Internationalisation (EN / PL)

The site is served in English and Polish. Every route lives under `src/app/[locale]/…` and is prefixed in the URL
(`/en/about`, `/pl/about`). `src/proxy.ts` redirects unprefixed URLs (cookie `NEXT_LOCALE`, then `Accept-Language`,
default `en`) and maps the old Polish URLs (`/katalog`, `/kariera`, `/aktualnosci`) to `/pl/...`.

## Reading the locale

- **Server pages / layouts** (`src/app/[locale]/**/page.tsx`): `params` is a Promise that includes `locale`.
  ```ts
  import { localeFrom, getDictionary } from "@/lib/i18n";
  type Props = { params: Promise<{ locale: string; slug?: string }> };
  export default async function Page({ params }: Props) {
    const locale = await localeFrom(params);
    const t = getDictionary(locale);          // UI strings
    const copy = getAboutCopy(locale);        // page copy (see below)
    …
  }
  export async function generateMetadata({ params }: Props): Promise<Metadata> {
    const locale = await localeFrom(params);
    return { title: …, description: … };      // localized
  }
  ```
  Static `export const metadata = {...}` must become `generateMetadata` so titles/descriptions translate.
- **Client components**: `useLocale()` and `useT()` from `@/components/i18n/I18nProvider`.
  ```tsx
  const locale = useLocale();           // "en" | "pl"
  const t = useT();                     // full dictionary for the current locale
  ```
- `generateStaticParams()` in nested dynamic routes keeps returning only its own segment (`{ slug }`); the layout provides the locales.

## Where strings live

1. **UI chrome and component labels** (buttons, form labels, placeholders, "Read more", aria-labels, sr-only text, status messages):
   the dictionary, `src/lib/i18n/dictionaries/`. Shared chrome (nav, footer, cookie banner, 404, `common`, `contacts`) is in `en.ts`/`pl.ts`.
   Area files in `dictionaries/areas/*.ts` hold the labels of one area and are merged into the dictionary under the same key:

   | key          | file                | used by                                                   |
   |--------------|---------------------|-----------------------------------------------------------|
   | `t.home`     | `areas/home.ts`     | home page sections, Hero                                   |
   | `t.pages`    | `areas/pages.ts`    | shared page blocks in `components/pages/*`, solutions, services |
   | `t.catalog`  | `areas/catalog.ts`  | catalog pages, configurator, 3D viewer, product cards       |
   | `t.company`  | `areas/company.ts`  | about, technology, contact (+ form), career                |
   | `t.news`     | `areas/news.ts`     | news, newsletter, legal pages                              |

   Each area file is `const en = {...}; const pl: typeof en = {...}; export const xArea = { en, pl };` – `en` defines the shape, `pl`
   must match it (TypeScript enforces it). Keys are camelCase; nest per component (`t.catalog.configurator.send`).

2. **Page copy and data** (headlines, paragraphs, feature lists, products, articles, legal text): content modules in `src/lib/content/`,
   typed with `Localized<T>` from `@/lib/i18n`:
   ```ts
   import { type Localized, type Locale, pick } from "@/lib/i18n";
   const copy: Localized<AboutCopy> = { en: {...}, pl: {...} };
   export const getAboutCopy = (locale: Locale) => pick(copy, locale);
   ```
   For big modules keep the languages in separate files (`catalog.ts` → `catalog.en.ts` + `catalog.pl.ts`, with `catalog.ts` exporting the
   types, `getProducts(locale)`, `getProduct(slug, locale)` …; getters take the slug first, then the locale). Slugs, hrefs, images, icons, SKUs, numbers and phone numbers are shared and
   never translated; only human-readable text is. Routes stay English in both languages (`/pl/catalog`, `/pl/services/cleaning`).

3. **Contacts**: `contacts`/`defaultContacts` in `src/lib/site.ts` carry role/note *keys*; components render `t.contacts[role]`.

## Polish copy rules

- Use the client's own Polish text first: `incoming/scrape/pl/*.txt` (home, about, technology, contact, career, catalog listing,
  cleaning, disinfection, inspection, training, franchise, news, privacy, terms). The live Polish catalog product pages are at
  `https://dcs-drone.com/katalog/<slug>` (see `scripts/scrape-site-pl.mjs` for a scraper to reuse).
- Where our English copy goes beyond the client's text, translate it faithfully into natural, professional Polish (the client writes in the
  direct "Ty" form: "Transformuj konserwację…", "Twojego biznesu"). Keep every number, claim, SKU and name identical to the English version.
  Never invent facts.
- Polish typography: proper diacritics (ą ć ę ł ń ó ś ź ż), „polskie cudzysłowy” optional, en dash with spaces (` – `) for dashes,
  decimal comma (`3,5 m`), unit spacing (`120 m`, `450 l`), dates `14 listopada 2026`.
- Headlines keep the same length/line count as English where a component depends on it (hero lines, 3-line titles) – shorten rather than
  overflow. Check visually at mobile widths if you change a headline.
- Files containing Polish letters, en dashes or other non-ASCII must be written with the Write/Edit tools (never Bash heredocs).

## Links

Always `import { Link } from "@/components/ui/Link"` (adds the locale prefix) – never `next/link` directly. Internal hrefs stay unprefixed
in content (`/catalog`, `/services/cleaning`); `Button href="…"` already goes through the wrapper. `localizeHref(href, locale)` is available for
places that need a string (e.g. `router.push`).
